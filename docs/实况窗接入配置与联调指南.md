# 凯格尔训练：HarmonyOS 实况窗接入、权限申请与联调指南

> 适用项目：`com.kaigeer.training`（凯格尔训练）  
> 目标：训练开始后，在状态栏胶囊、通知中心和锁屏展示当前训练状态；点击后回到训练页；锁屏展开时展示沉浸式训练信息。  
> 当前工程目录：`/Users/yujiantao/DevEcoStudioProjects/bang`

## 0. 先记住四个结论

1. **实况窗不是普通通知，也不是单独写一个 Manifest 权限就能打开的功能。**它需要：
   - AppGallery Connect 中申请并通过实况窗权益；
   - 重新生成/下载包含权益的 Profile；
   - 使用这份 Profile 对 HAP 签名；
   - 用户设备上的实况窗开关已打开。

2. **本地实况窗不强制依赖 Push Kit。**训练由用户主动点击“开始训练”触发，训练进程和系统计时器可以直接创建、更新、结束实况窗。

3. **Push Kit 是可选的增强方案。**如果训练状态需要在应用进程被系统回收后仍由云端更新，才需要 Push Kit、Push Token、服务端和鉴权令牌。当前凯格尔训练的 5 秒收紧/5 秒放松训练，不需要为了本地倒计时强行接入 Push。

4. **实况窗必须用真机验收。**官方文档明确说明实况窗不支持模拟器；Push Kit 的实况窗消息同样不能用模拟器验证。

官方入口：

- [Live View Kit 简介与准入说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V13/liveview-introduction-V13)
- [申请实况窗正式权限](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/liveview-formal-authority)
- [实况窗接入联调测试](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/liveview-joint-commission-test)
- [Live View Kit ArkTS API](https://developer.huawei.com/consumer/cn/doc/harmonyos-references-V5/liveviewmanager)

## 1. 我们这款应用的整体方案

### 1.1 当前采用的本地方案

```text
用户点击开始训练
        ↓
申请/确认通知授权
        ↓
启动 audioPlayback 长时任务，保证训练计时和语音继续运行
        ↓
检查 liveViewManager.isLiveViewEnabled()
        ↓
liveViewManager.startLiveView()
        ↓
动作切换、暂停、恢复时调用 updateLiveView()
        ↓
训练完成或用户退出时 stopLiveView()
```

系统 Live View 的 `timer` 字段负责胶囊中的秒级倒计时，所以不应该每秒调用一次 `updateLiveView()`。我们只在“准备 → 收紧 → 放松 → 下一次 → 暂停/恢复”等状态变化时更新实况窗。

### 1.2 本地实况窗和 Push Kit 的区别

| 方案 | 是否需要服务端 | 应用进程被杀后能否更新 | 当前是否必需 |
| --- | --- | --- | --- |
| Live View Kit 本地创建/更新 | 不需要 | 依赖应用进程和长时任务 | **当前训练必需** |
| Push Kit 更新已创建的实况窗 | 需要 | 可以由云端更新 | 可选增强 |
| Push Kit 远程创建实况窗 | 需要 | 可以 | 不适合当前 `WORKOUT` 场景 |

官方当前说明：本地实况窗创建依赖应用进程；Push Kit 可用于后续更新。通过 Push Kit 远程创建目前仅支持 `FLIGHT`、`TAXI`、`TRAIN` 等场景，训练场景应先用 Live View Kit 本地创建。

## 2. AppGallery Connect 配置与权限申请

### 2.1 基本准备

在 AppGallery Connect 中确认以下信息完全一致：

- 项目：当前 AGC 项目。
- 应用包名：`com.kaigeer.training`。
- 应用类型：HarmonyOS Application。
- DevEco Studio 工程中的 bundleName 与 AGC 应用包名一致。
- 使用真机的华为账号、开发者账号和 AGC 项目账号属于同一套测试链路。

如果包名、Profile 所属应用或签名证书不一致，最常见的结果是安装失败、实况窗权限不生效，或者 `startLiveView()` 返回权限错误。

### 2.2 申请实况窗权益

在 AGC 的应用服务/开放能力管理中，按 Live View Kit 的流程完成：

1. 进入目标项目和 `com.kaigeer.training` 应用。
2. 开通/申请 Push Kit 服务（如果页面流程要求先开通，这是项目级能力）。
3. 进入 Live View Kit 的实况窗权益申请入口。
4. 申请当前业务场景：**运动锻炼（`WORKOUT`）**。
5. 填写真实的使用场景、展示内容、通知频率和结束条件。
6. 申请联调测试权限。
7. 联调通过后，再申请正式权限。

申请原因建议这样写：

> 凯格尔训练是一款由用户主动启动的短时坐姿盆底肌训练工具。用户开始训练后，应用需要在训练进行期间展示当前动作、剩余秒数、当前组数和次数，方便用户在锁屏、状态栏和通知中心快速查看并返回训练。训练由用户主动开始，每次训练约 3–10 分钟，最长不超过 8 小时；训练完成、用户主动结束或暂停后，实况窗会同步更新或结束。展示内容仅为训练状态，不包含广告、营销或无关信息。

申请页面如果要求填写通知信息，可使用：

| 项目 | 建议内容 |
| --- | --- |
| 场景 | 用户主动开始的坐姿凯格尔/盆底肌训练 |
| 实况窗事件 | `WORKOUT` |
| 标题 | `凯格尔训练` |
| 进行中内容 | `收紧 · 第1/3组 · 第2/10次` |
| 辅助提示 | `自然呼吸 · 腹部和臀部放松` |
| 暂停内容 | `已暂停 · 点击继续` |
| 完成内容 | `本次训练已完成` |
| 触发方式 | 用户点击“开始训练”后触发 |
| 更新频率 | 动作切换、暂停/恢复、组/次数变化时更新；秒数使用系统计时器 |
| 结束条件 | 完成训练、用户点击结束或训练状态失效 |

同时按审核要求准备应用分类信息截图。实况窗申请和代理提醒申请是两条不同的审核链路，不能用同一段理由替代。

### 2.3 Push Kit 是否必须申请

对当前版本：

- **本地创建实况窗：不需要服务端 Push Token。**
- **如果后续要支持进程被杀后由云端更新：需要开通 Push Kit、获取 Token、准备服务端鉴权和推送接口。**
- Push Kit 权益和 Live View 权益是相关但不同的能力，不能把开通 Push Kit 当成已经获得实况窗权益。

Push Kit 开通入口：[开通推送服务](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/push-config-setting)。

### 2.4 权益通过后必须重新生成 Profile

这是之前最容易踩坑的地方：**AGC 审核通过不代表本地旧 Profile 自动增加权限。**

正确流程：

1. AGC 权益通过后，重新生成或下载开发/调试 Profile。
2. 如果进入发布阶段，重新生成发布证书和发布 Profile。
3. 将新的 `.p7b`、`.cer`、`.p12` 配置到 DevEco Studio。
4. 确认 `build-profile.json5` 使用的是包含实况窗权益的签名配置。
5. 清理/重新构建 HAP，再安装到真机。

`auto` 自动签名适合快速开发验证，但不能把它当成正式上架签名的替代品。正式版本应使用 AGC 生成的正式证书、Profile 和手动签名配置。

## 3. 工程侧配置

### 3.1 `module.json5` 中的关键配置

当前工程相关配置如下，密码和证书内容不要写入文档或提交到仓库：

```json5
{
  "module": {
    "name": "entry",
    "type": "entry",
    "deviceTypes": ["phone", "tablet", "2in1"],
    "requestPermissions": [
      {
        "name": "ohos.permission.PUBLISH_AGENT_REMINDER"
      },
      {
        "name": "ohos.permission.KEEP_BACKGROUND_RUNNING"
      }
    ],
    "abilities": [
      {
        "name": "EntryAbility",
        "backgroundModes": ["audioPlayback"]
      }
    ],
    "extensionAbilities": [
      {
        "name": "LiveViewLockScreenExtAbility",
        "srcEntry": "./ets/extensionability/LiveViewLockScreenExtAbility.ets",
        "type": "liveViewLockScreen",
        "exported": true
      }
    ]
  }
}
```

注意：

- `liveViewLockScreen` 扩展能力用于锁屏沉浸态，不是普通 Page，也不是通知扩展。
- `LiveViewLockScreenExtensionAbility` 在独立子进程中运行，不能在其中调用通知、窗口、后台任务、网络上传下载等 API。它只负责读取参数并渲染锁屏页面。
- 如果只需要状态栏胶囊和通知中心卡片，可以暂时不接锁屏扩展；本项目已经接入，所以需要保留上述配置。

### 3.2 权限清单怎么理解

| 配置/权限 | 用途 | 是否为实况窗权益 |
| --- | --- | --- |
| `ohos.permission.KEEP_BACKGROUND_RUNNING` | 让训练计时/语音通过长时任务继续运行 | 否，是后台训练配套权限 |
| `backgroundModes: ["audioPlayback"]` | 声明本项目使用音频播放型长时任务 | 否，是长时任务场景声明 |
| `ohos.permission.PUBLISH_AGENT_REMINDER` | 每日提醒/代理提醒 | 否，与实况窗申请分开审核 |
| `notificationManager.requestEnableNotification()` | 请求用户打开通知能力 | 否，是用户侧通知开关 |
| AGC Live View 权益 | 允许 `startLiveView/updateLiveView` | **是，核心权益** |
| Push Kit 权益 | 让服务端通过 Push 更新 | 仅 Push 方案需要 |
| `ohos.permission.INTERNET` | 需要自行联网调用服务端时使用 | 仅接入自有服务端/Push 辅助逻辑时考虑 |

不要为了“让实况窗出现”随意添加麦克风、定位、相机或存储权限。当前训练功能不需要这些权限。

### 3.3 签名配置

`build-profile.json5` 应使用类似下面的结构，路径替换为本机实际文件；密码只保存在本地，不要复制到聊天、截图或 Git：

```json5
{
  "app": {
    "signingConfigs": [
      {
        "name": "kaigeerRelease",
        "type": "HarmonyOS",
        "material": {
          "storeFile": "/path/to/kaigeer.p12",
          "storePassword": "<本地密钥库密码>",
          "keyAlias": "<AGC 中的 Key Alias>",
          "keyPassword": "<本地私钥密码>",
          "signAlg": "SHA256withECDSA",
          "profile": "/path/to/KaigeerTraining.p7b",
          "certpath": "/path/to/kaigeer.cer"
        }
      }
    ],
    "products": [
      {
        "name": "default",
        "signingConfig": "kaigeerRelease"
      }
    ]
  }
}
```

字段含义：

- `storeFile`：PKCS#12 密钥库文件，也就是 `.p12`。
- `keyAlias`：密钥库中具体私钥条目的别名，不是包名。创建密钥时由你设置，AGC/DevEco 配置必须一致。
- `storePassword`：打开 `.p12` 密钥库的密码。
- `keyPassword`：读取 `keyAlias` 对应私钥的密码。
- `profile`：AGC 生成的 `.p7b` 权限 Profile。
- `certpath`：对应签名证书 `.cer`。

DevEco/签名工具要求密码长度满足当前版本规则；不要用过短密码，也不要把密码写成项目说明文档中的固定示例。

## 4. 代码工作流

### 4.1 创建 WantAgent

实况窗点击后要回到训练页，因此需要构造 `WantAgent`：

```ts
const info: wantAgent.WantAgentInfo = {
  wants: [{
    bundleName: 'com.kaigeer.training',
    abilityName: 'EntryAbility',
    parameters: { restoreTraining: 'true' }
  } as Want],
  actionType: wantAgent.OperationType.START_ABILITY,
  requestCode: 20880915,
  wantAgentFlags: [wantAgent.WantAgentFlags.UPDATE_PRESENT_FLAG]
};

const agent: WantAgent = await wantAgent.getWantAgent(info);
```

`bundleName`、`abilityName` 和实际工程必须一致；否则胶囊能显示，但点击不能正确回到训练页。

### 4.2 构造本地 Live View

核心字段：

```ts
const liveView: liveViewManager.LiveView = {
  id: 20880915,
  event: 'WORKOUT',
  sequence: 1,
  isMute: true,
  timer: {
    time: remainingSeconds * 1000,
    isCountdown: true,
    isPaused: paused
  },
  liveViewData: {
    primary: {
      title: '收紧 · \${placeholder.timer}',
      content: [{ text: '第1/3组 · 第2/10次' }],
      keepTime: 3600,
      clickAction: agent,
      extensionData: {
        text: '自然呼吸 · 腹部和臀部放松',
        type: liveViewManager.ExtensionType.EXTENSION_TYPE_COMMON_TEXT,
        clickAction: agent
      },
      layoutData: {
        layoutType: liveViewManager.LayoutType.LAYOUT_TYPE_PROGRESS,
        progress: 20,
        color: '#FF087F73',
        backgroundColor: '#26087F73'
      }
    },
    capsule: {
      type: liveViewManager.CapsuleType.CAPSULE_TYPE_TIMER,
      status: 1,
      icon: 'live_view_lock.png',
      title: '凯格尔训练',
      content: '收紧 · 1/3组',
      time: remainingSeconds * 1000,
      isCountdown: true,
      isPaused: paused,
      isContentDisplayed: true,
      backgroundColor: '#FF087F73'
    }
  }
};
```

字段规则：

- `id`：同一个训练实况窗的唯一 ID；更新和结束必须沿用。
- `event`：当前使用 `WORKOUT`，不能写成外卖或订单场景。
- `sequence`：每次更新必须大于上一次，不能回退。
- `timer`：适合秒级倒计时，避免每秒发送一次更新。
- `primary.content`：展开卡片中的完整信息。
- `capsule.content`：顶部胶囊中的短信息，避免塞入过长文本。
- `layoutData.progress`：整天训练计划的整体进度，不要只计算当前组。
- `clickAction`：点击胶囊和卡片回到 `EntryAbility`。

### 4.3 创建、更新、结束

```ts
await liveViewManager.startLiveView(liveView);

// 动作、暂停、组数或次数变化时：sequence + 1
liveView.sequence += 1;
await liveViewManager.updateLiveView(liveView);

// 训练完成或用户主动退出
liveView.sequence += 1;
await liveViewManager.stopLiveView(liveView);
```

建议调用顺序：

1. 先 `isLiveViewEnabled()`。
2. 再 `startLiveView()`。
3. 只有创建成功后才 `updateLiveView()`。
4. 更新失败时检查是否是实况窗不存在、序列号错误或权益失效。
5. 最后调用 `stopLiveView()`，再停止后台长时任务；若要立即关闭而不保留结束态，将结束态的 `primary.keepTime` 设为 `0`。

训练交互约定：动作统一通过 `WantAgent` 传递 `liveViewAction` 参数回到 `EntryAbility`，再由训练页切换状态。部分 6.1 进度模板设备虽然接受 `layoutData.serviceButtons` 字段，但不会把服务按钮绘制出来，因此本项目把“暂停训练/继续训练/继续下一组/完成训练”放进 `primary.extensionData` 的胶囊文本扩展区，保证右上角始终可见且可点击。单组完成时使用结束态 `stopLiveView()`，将 `keepTime` 设为短暂保留时间；用户点击动作后再进入下一组或返回首页。

### 4.4 锁屏沉浸态

`primary.liveViewLockScreenAbilityName` 指向 `module.json5` 中的扩展 Ability，参数通过 `liveViewLockScreenAbilityParameters` 传递：

```ts
liveViewLockScreenAbilityName: 'LiveViewLockScreenExtAbility',
liveViewLockScreenAbilityParameters: {
  phase: '向上提起',
  progress: '第1/3组 · 第2/10次',
  remaining: '5',
  hint: '自然呼吸 · 腹部和臀部放松'
}
```

扩展 Ability 在 `onSessionCreate()` 中读取 `want.parameters`，放入 `LocalStorage`，再调用：

```ts
session.loadContent('pages/LiveViewLockScreenPage', storage);
```

锁屏扩展页面只做展示，不要在里面启动计时器、调用通知 API、启动后台任务或请求网络。

## 6. 真机联调流程

### 6.1 安装前检查

- 使用真实华为手机或平板，不能用模拟器验证实况窗。
- 设备系统为 HarmonyOS NEXT 及以上，并且在实况窗支持范围内。
- 设备已连接 DevEco Studio，设备状态为在线。
- HAP 使用包含实况窗权益的 Profile 签名。
- 设备设置中允许应用通知。
- 系统实况窗总开关已打开。
- 应用第一次成功创建过实况窗后，再去系统设置中查找应用开关。

### 6.2 推荐测试步骤

1. 清理旧版应用或覆盖安装最新签名 HAP。
2. 打开“凯格尔训练”，确认首页正常。
3. 点击“开始训练”。
4. 等待准备倒计时进入“收紧”。
5. 按 Home 键回到桌面，观察顶部胶囊。
6. 下拉通知中心，展开实况窗卡片。
7. 锁屏后观察锁屏实况窗，长按或点击测试沉浸态和回到应用。
8. 点击暂停，再恢复，确认倒计时和文案同步。
9. 完成一组，确认实况窗停止或进入下一组逻辑。
10. 点击结束训练，确认胶囊、卡片和后台长时任务都结束。

### 6.3 日志观察点

建议搜索这些日志：

```text
Live View enabled=
Live View start failed
Live View recovery failed
Live View publish failed
Live View stop failed
Training background task unavailable
```

开发期间可以在 DevEco Studio 的 Log/Hilog 窗口观察；也可以使用连接真机的 `hdc hilog`。不要把包含证书密码、Token 或用户数据的完整日志上传到公开渠道。

## 7. 常见错误与处理办法

| 错误/现象 | 原因 | 处理 |
| --- | --- | --- |
| `1003500005` | 实况窗权益未生效 | 检查 AGC 申请状态、应用包名、设备开关，并重新下载包含权益的 Profile 后重新签名 |
| `1003500004` | 实况窗开关关闭 | 打开系统实况窗开关；应用首次成功创建前，设置页可能不会出现应用项 |
| `1003500006` | 相同 ID 的实况窗已存在 | 先调用 `getActiveLiveView()` 恢复并更新，或正确结束旧实况窗 |
| `1003500009` | 更新/结束时实况窗不存在 | 确保先 `startLiveView()`；不要把旧 ID 当成新会话使用 |
| `1003500011` | `sequence` 不递增 | 每次更新都使用大于当前值的序列号，并在进程内持久化当前序列 |
| 设置中找不到应用 | 还没有成功创建过实况窗、权益/Profile不匹配或系统开关关闭 | 先真机成功开始一次训练，再检查系统实况窗设置 |
| 模拟器完全没有实况窗 | 官方不支持模拟器实况窗 | 换真实手机/平板验证 |
| `Install Failed: no signature file` | 安装了 unsigned HAP | 使用 `entry-default-signed.hap`，检查签名配置和 Profile 路径 |
| 点击胶囊不回应用 | WantAgent 的 bundleName/abilityName 不匹配 | 改为实际的 `com.kaigeer.training` 和 `EntryAbility` |
| 卡片显示但不更新 | 更新调用失败、序列号错误或进程被回收 | 先查 Hilog；本地方案需要长时任务，进程被杀后的云端更新要接 Push Kit |
| 锁屏沉浸态白屏 | ExtensionAbility 名称、类型、页面路径或参数不一致 | 检查 `liveViewLockScreen` 配置、`onSessionCreate()` 和 `loadContent()` |

## 8. Push Kit 增强方案（以后需要时再做）

如果以后希望“应用进程被系统回收后，训练状态仍能由云端更新”，流程是：

```text
客户端集成 Push Kit
        ↓
获取 Push Token
        ↓
把 token、用户标识、liveViewId、event 上报业务服务端
        ↓
客户端先用 Live View Kit 创建本地实况窗
        ↓
服务端生成鉴权令牌
        ↓
服务端调用 Push Kit 实况窗更新接口
        ↓
operation=1 更新，operation=2 结束
```

Push 更新至少要维护：

- `pushToken`；
- `liveViewId/activityId`；
- `event`；
- 业务状态；
- 单调递增的 `version/sequence`；
- 用户主动结束、训练完成和超时结束状态。

Push Kit 文档：

- [开通推送服务](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/push-config-setting)
- [Push Kit 简介与业务流程](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/push-kit-introduction)
- [通过 Push Kit 更新实况窗](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/liveview-update-by-push)
- [Push Kit 推送实况窗消息](https://developer.huawei.com/consumer/en/doc/harmonyos-guides-V14/push-update-liveview-V14)

对于凯格尔训练，Push Kit 的合理使用场景是“训练计划云端同步、跨设备状态或长时间课程状态”，不是用来替代本地 5 秒计时器。

## 11. 针对当前项目的建议顺序

当前版本建议按下面顺序继续：

1. 先使用现有本地 Live View 方案，把真机胶囊、卡片、锁屏和结束流程验收完整。
2. 确认 AGC 正式实况窗权益和发布 Profile 已生效。
3. 上架前再决定是否接 Push Kit；如果只是单机训练计时，可以暂不增加服务端复杂度。
4. 如果接 Push，先做“本地创建 + Push 更新/结束”，不要直接用 Push 远程创建 `WORKOUT` 实况窗。

这样可以把“训练计时”“后台继续”“实况窗展示”“每日提醒”“云端推送”拆成清晰的能力边界，后续定位问题时不会把代理提醒、通知权限、后台长时任务和实况窗权益混在一起。
